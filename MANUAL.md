## Using it

### The launch window

Each normal start opens with a small window: the version, the Spectrum animation and a quotation. **OK** or Return goes on to the program, and nothing else starts until you do; Escape or closing it leaves. Click the name under a quotation to see where it comes from. **Build & licence** gives the full version and licences. It is left out in safe mode, after a crash and on a restart. For a computer that starts OmaBroadcast with no one there, set `OMABROADCAST_NO_LAUNCH_WINDOW=1` in its environment.

### Prompter

**Tools → Prompter** opens a window of its own for the person on camera; put it beside the camera or over the picture. Drag its top bar to move it and an edge or corner to resize it. **Load…** takes a text or Markdown file (`.txt`, `.md`), and the file is opened again next time. **Play** scrolls the words past the mark on each side of the window. Space starts and pauses, Up and Down change the speed, Home goes back to the start, and the wheel or a drag finds a place. Speed is lines in ten seconds, so changing the size of the words keeps the pace. The window is never part of the picture, so recordings, streams and the virtual camera cannot show it. On Hyprland it is also kept out of screen captures, where it shows as a black box, so put it on a screen you are not capturing; elsewhere the window warns that a capture of its screen can show it. Word documents need saving as text first. To start and pause it with a hotkey or a foot pedal, its actions are in **Tools → Hotkeys…** and `omabroadcast ctl`.

### Set up for…

On a fresh install OmaBroadcast first asks what it is for; **Tools → Set up for…** asks again any time. Pick one of **Streaming**, **Recording**, **Tutorials and screencasts**, **Recording for editing**, **Game replays**, **Webcam and video calls** or **Light recording**, then the display whose size the canvas takes, whether to show that display in the studios (off unless the choice is about the screen), a camera if you want one, any sound you want (the microphone and the desktop's sound are off until you choose them; a camera never brings its own sound; a microphone you pick is added to Sources beside the camera, while **Automatic** follows the desktop's default input and shows in the mixer only), and for a stream the service, server and key. **Check this machine** tries the encoders here at the sizes that could suit, as they really run, and for a stream measures your upload with a short test that never goes live (Twitch's test mode, or your own server; for other services type your upload speed from a speed test site). It then shows what it will set and why: the canvas, frame rate, which encoder at what size and quality, the stream's size and bitrate (a quarter of your upload kept spare, within what the service takes), audio tracks, the replay buffer or the virtual camera. **Create** makes a new profile and a new studio collection with starter studios (for a stream: *Starting soon*, *Live*, *Be right back* and *Thanks for watching*) that hold only what you chose: pick a camera alone and you get one studio with the camera in it. A display you asked for is chosen in the desktop's picker when the studios open. What you had stays as it was, a profile and a collection away.

1. **+ Display** or **+ Window** opens the share picker. Allow it once; the choice is remembered and re-opens without a prompt next time. The picker opens only when you ask for it: if the desktop has forgotten a choice, the source says "not chosen yet" until you right-click it and use **Choose display…** or **Choose window…**.
2. Add your sound: click **+** in Sources and choose an input under **Microphone or audio input**, or **Desktop sound**. Every picture and every sound is chosen in that one menu, and, unless **Set up for…** added them for you, nothing is assumed: the mixer shows only what you have added, what is not added is not captured, and until you add something the mixer says there is no sound and recordings are silent. A camera or capture card brings its picture alone; its own microphone is listed with the other inputs. An input already in use is greyed out. A sound added this way plays in the studio you added it to; **Sound for every studio…** in the same menu keeps one in all of them. **Desktop sound** is in every studio. **X** on a Desktop, Microphone or Sound for every studio strip removes it; any other sound is a source, so right-click it in Sources and choose **Remove**. Each strip has its own fader and mute.
3. **Record** (or `Ctrl+R`). The title bar shows the running time; the status line shows frames, encode time, file size and how long the disk will last. A recording won't start with under 512 MB free; while one runs it warns once when about five minutes (or 2 GB) are left, and stops and saves the file before the disk is full rather than leave it broken.
4. **Stop recording**. The file is named by date and time in `~/Videos/OmaBroadcast`, unless you change the name pattern or folder in Settings.

While recording, the **Record** menu can **Pause recording** (the paused stretch is left out and the file plays straight through), **Start a new file** at the next keyframe, and **Mark a chapter** in formats that keep chapters.

### Sizes

recordings and each stream can go out smaller (or larger) than the canvas: **Size** on the Recording page and in each stream's settings offers the canvas's shape at standard heights, e.g. a 1080p stream from a 4K canvas. The picture is scaled on the graphics card, so it costs little; a stream service's limits are checked against the size it is sent at. Shrinking averages the canvas's pixels in linear light by default, which keeps fine detail from shimmering; **Scaling** on the Video page picks a sharper filter.

### Colour and HDR

**Settings → Video** sets the colour every recording and stream carries. The canvas itself always works in floating point, linear light, so these choices only decide what goes out:
- **Colour format**: how the picture is laid out for the encoder. **Automatic** uses the encoder's usual layout (and a 10-bit one for HDR). NV12 and I420 are 8-bit 4:2:0, which plays everywhere; I444 keeps full colour detail for sharp text and screen recordings; P010 and I010 are 10-bit 4:2:0, which keeps smooth gradients from banding; P216 and P416 are 16-bit 4:2:2 and 4:4:4; BGRA is 8-bit RGB. Only the layouts the recording encoder actually opened with are offered (`omabroadcast --probe` lists them per encoder).
- **Colour space**: **Rec. 709** (the default) is HD video; **sRGB** is the same picture labelled for computer screens; **Rec. 601** is for standard-definition video. The three carry the same picture the app has always recorded, with each one's own label (and Rec. 601's own colours). **Rec. 2100 (PQ)** is HDR10, for HDR players and services such as YouTube; **Rec. 2100 (HLG)** is the broadcast HDR that also looks right on SDR screens. HDR needs a 10-bit (or 16-bit) format and an encoder that takes one, typically HEVC or AV1; a choice that can't be recorded is refused and the status line says why.
- **Range**: **Limited** (black at 16, white at 235 in 8 bits) is what players and TVs expect; **Full** uses every code, for players set up for it. BGRA is always full.
- **SDR white** (203 nits, the broadcast reference) is how bright your desktop, cameras, pictures and text are in an HDR recording, and what HDR sources are measured against. Raise it if they look dim beside HDR video. **HDR peak** (1000 nits) is the brightest an HDR recording goes: PQ recordings are held there and tell players so (mastering display and light levels), and HLG is made for a display that bright.

The note under these settings says what recordings will carry and through which encoder. The virtual camera and the preview stay 8-bit SDR whatever is chosen. HDR video files and 10-bit capture cards keep their brightness and precision on the canvas: an HDR source shows its highlights above SDR white in an HDR recording; for an SDR recording, give it an **HDR tone map** filter so its highlights roll off instead of clipping. The canvas mixes in BT.709 colours, so the most saturated BT.2020 colours of an HDR source are held to the nearest BT.709 colour.

### MP4 copies

MKV is the safest format to record in, but some editors and players want MP4. Tick **Also make an MP4 copy when it ends** under **Settings → Recording** and each recording gets an MP4 beside it as soon as it finishes; **File → Remux recordings…** does the same for any recordings you choose. Nothing is encoded again, so it takes seconds, and chapters come along. The original is left as it was.

### Replay buffer

**Record → Start the replay buffer** keeps the last stretch of the program in memory, so you can save something that has just happened without recording everything. **Save replay** (the toolbar button that appears, the tray menu, or **Ctrl+Shift+R**) writes it to the recordings folder in the recording format, named like a recording with **Replay** in front. **Settings → Replay buffer** sets how many seconds it keeps, the most memory it may use, and what goes before and after the name. A save starts on a keyframe, so it can reach a little further back than asked. It uses the recording's encoder settings, and shares one encoder with a recording running at the same time.

### Virtual camera

**Stream → Start the virtual camera** (or the camera button in the toolbar) offers the program as a camera called **OmaBroadcast Camera**, which browsers and calling apps that use PipeWire cameras can choose like a webcam. The button lights up while it is on; the status line says when an app is using it, and nothing extra is done while none is. By default it shows the program; **Stream → Virtual camera settings…** can make it show studio mode's preview, another studio (so you can switch the live one without the call seeing it) or one source on its own, fitted to the canvas.

### Streaming

add each place you go live to in **Settings → Streaming → Add a stream…**: Twitch, YouTube, Facebook Live, Restream, or a server of your own (`rtmp://`, `rtmps://`, `srt://`, or `https://` for WHIP or HLS). Paste the stream key from the service's dashboard; it is kept in your desktop keyring (gnome-keyring or KWallet), not in the profile, and the window never shows it again. With no keyring it stays in the profile, a file only your account can read. Choose the encoder, bitrate and audio track; anything the service would refuse or warns against (codec, bitrate, size, frame rate, keyframe interval) is shown as you edit, and **Keep to the service's limits** (on by default) lowers the bitrate, keyframe interval and size to what it publishes and picks an encoder it takes. A server of your own can ask for a name and password (RTMP or HTTP), or an SRT passphrase; the password goes in the keyring with the key. **Go live** sends the live studio to every stream that is switched on, at once, each with its own encoder settings; outputs asking for identical settings share one encoder. A locked keyring asks first, and the streams start once you answer; everything else keeps running while it waits. A service with no key to send is refused here rather than at its door. If the connection drops it reconnects, waiting a little longer each time, and resumes at a fresh keyframe; a recording carries on regardless. When the network can't keep up, pictures are dropped up to the next keyframe rather than letting the stream fall behind, and **Lower the bitrate when the network can't keep up** reduces the encoder's bitrate until it recovers. Only NVENC and x264 can change their bitrate while running, and an encoder another output shares holds its rate; with any other encoder the sheet says so and the stream only drops pictures. Streams are stereo: a surround mix is folded down for them, with the centre and surrounds at -3 dB and no LFE. A stream **Delay** holds everything back by that many seconds (the sheet says how much memory that takes); with **Keep what it holds through a reconnect**, a dropped connection carries on from where viewers stopped seeing it instead of jumping to now, and the delay grows by the outage. Under **Network**, choose the local address to send from, IPv4 or IPv6 only, and low-latency sending for RTMP. **Record while streaming** starts a recording with the stream; **Stop recording when the stream ends** ends it too. **Keep a replay buffer while streaming** runs one for as long as you are live. The status line shows each stream's bitrate, any dropped frames and its delay. WHIP (WebRTC) needs H.264 video and sends Opus sound. A server of your own can also name any FFmpeg **Container** to send in, to any address FFmpeg writes to (`udp://`, `tcp://`, `rtp://`, a file…), and any stream takes the container's or connection's own `key=value` options, such as `pkt_size=1316` for UDP; one that nothing takes stops the stream at once and names it.

### Text sources

plain text displays literally, with font, size, wrapping, alignment, colour, gradient, outline and shadow controls. Enable **Rich text (HTML)** to enter markup such as `<b>Live</b> <span style="color:#72dfbd">today</span>`, including mixed fonts, headings, lists and colour emoji. The editor keeps the markup visible for editing; the preview shows the formatted result. Formatting uses [Qt's supported HTML subset](https://doc.qt.io/qt-6/richtext-html-subset.html). A source gradient overrides the rendered colours. **Smooth text edges** controls antialiasing. **From a file** follows updates to a text or HTML file; relative inline images resolve beside it. **Last … lines** reads the last physical lines of a file (0 reads the whole file, up to its first 1 MB). Only ordinary files are read: a pipe or a device shows as such in the source's state. Formatting settings and markup support undo and collection save/load.

### Browser sources

**Studio → Add browser** (or **+ → Browser** in Sources) shows a web page, or with **Local file** an HTML file from this computer, at the size you set (the canvas's at first) and up to the frame rate you set; a page that does not change sends no pictures. Parts of the page that are transparent stay transparent over what is beneath. **Custom CSS** is added to every page it loads and applies as you type; the starting CSS makes the page's background clear. **Reload** loads it again, fetching everything afresh. **Interact…** opens the page in a window of its own: click, scroll and type in it (to sign in, press a button or dismiss a notice), and what you do there is what goes out; while that window has the keyboard, OmaBroadcast's own shortcuts leave it alone. A page's own form works there; a browser's password box or file chooser cannot be shown, so a page that asks for one is refused and the source says so. **Shut down when not visible** closes the page while no live studio shows it, saving memory and processor time, and loads it afresh when shown; **Reload when it becomes visible** starts an animation from its beginning each time it comes on. The page's sound is its own channel in the mixer (fader, mute, filters, tracks) and never plays on your speakers by itself; if that cannot be arranged, the page is muted. Each page runs in a separate helper program, so one that crashes does not take OmaBroadcast with it: it starts again by itself. Sign-ins and site data are kept per source. Browser sources need Qt WebEngine (`qt6-webengine`); without it they are hidden, and a collection that has one says what it needs. A local page is one of the collection's files, so **Find missing files** relinks it.

### Custom browser docks

**View → Docks → Custom browser docks…** adds a page (a chat, an alerts dashboard) by name and address as a dock of its own. It sits in the dock columns like the others: fold, resize, move and close it from its ⋮, which also reloads its page or edits the list. Docks are remembered for every collection and share one set of sign-ins, kept between runs. Web links you click that want a window of their own open in your web browser; a page cannot open anything there by itself. They also need Qt WebEngine.

### Inactive sources

enable **Close when not visible** on media to close its decoder or network listener and release queued audio and pictures when its last visible reference disappears. It reopens from the beginning when shown again. **Unload when not visible** releases an image's pixels, GPU texture and animation; showing it reloads the current file. These options are off by default. Activity includes nested studios and groups, and a source shared by two visible layouts stays active across a studio switch. **Start again when it becomes visible** restarts file playback only on an inactive-to-active change; with both media options off, hidden files continue advancing silently. These settings support undo and collection save/load.

### Copying sources

select sources in one studio or group and choose **Edit → Copy sources** (`Ctrl+C`). **Paste reference** (`Ctrl+V`) adds them to the current studio with shared live source settings; **Paste duplicate** (`Ctrl+Shift+V`) makes independent sources from the copied settings. Both preserve stacking, placement, visibility and locks, and paste in one undo step. Groups receive private item trees in both modes; duplicates also copy nested studios and their sources. Multiple references to one source stay shared within a duplicate. Copying a group includes its children once. The source clipboard belongs to the current collection and clears when it changes; if an original source disappears, copy it again before pasting references. Text fields keep their normal copy/paste shortcuts.

### Blending and scaling

select an item and use **Blend space** to choose **Linear light** (the default) or **sRGB** opacity mixing. Half-transparent white over black appears around 188/255 in linear light and 128/255 in sRGB. The choice works with every blend mode and follows undo, saved collections and copied placement. **Scaling → Point (nearest)** keeps individual pixels crisp; the other scaling filters interpolate colours with their transparency, preventing invisible pixels from tinting or darkening edges. Scaling remains in linear light in either blend space.

### Finding your way

hover any control for a short explanation of what it does. The Source panel is in sections (the source itself, text effects, picture, transform, crop, blending and so on): click a section's heading to fold it away or open it, and the app remembers which you keep open.

### Docks

the Studios, Transitions, Sources, Source, Audio mixer and Stats panels are docks. Click the arrow beside a dock's name (or the name) to fold it down to its title bar when you don't need it; the docks around it take the room, and it opens again where it was. Drag the lines between them, or between a side and the preview, to resize. The ⋮ in a dock's header moves it to the other side, up or down, or closes it; **View → Docks** reopens closed docks, locks them in place and resets the layout. The layout is remembered.

### Stats

open **View → Docks → Stats** to see how hard the machine is working: CPU use by OmaBroadcast and by everything, how busy each graphics card is (where the system reports it; otherwise "not available"), memory, the disk space left where recordings go and, while recording, how many minutes that lasts at the current rate. Below that: frames per second, how long each frame takes to draw, frames that came late, and for the recording, each stream, the replay buffer and the virtual camera how long a frame takes to encode, how far sending is behind and how many frames were dropped. It is closed to begin with, updates about once a second, and reads nothing while closed or folded. If a recording misses more than 1% of its pictures, the status line says so when it is saved (`Saved x.mkv, short of 90 pictures of 181: this computer could not keep up. See Stats.`), and the log gives the count whenever any are missing. Another program working the graphics card hard is a common cause.

### Graphics

**Settings → General → Graphics** picks the graphics card that puts the picture together. **Automatic** (the default) uses a discrete card when there is one, and on a laptop running on battery the integrated one, so the bigger card can stay asleep. Plug in or unplug and the picture moves to the card that suits, once nothing is recording, streaming, buffering a replay or feeding the virtual camera; the bottom-right corner names the card, with "on battery" when the battery chose it. Choose a card by hand to keep everything on it, or **Processor only** to compare (a source using Remove background (AI) is then hidden). With a card chosen, or on battery, recordings and streams also prefer an encoder on that card over a better format on another one. The change restarts the picture straight away (and checks the encoders again, a few seconds), so it is shut while recording, streaming, the replay buffer or the virtual camera run. The line under the box, the Stats dock and `omabroadcast --probe` say which card is in use and why. An encoder on another card than the one putting the picture together gets every frame copied across, which is slower (at 4K it may not keep up); the Recording page says so when that is the case.

### Studios

click one to make it live, double-click to rename, right-click to duplicate, reorder, remove or show it inside the live studio. The button beside **+** switches between a list and a grid of tiles; the choice is remembered.

### Transitions

a change of live studio goes through the transition chosen in the **Transitions** dock, over its **Duration** (Fade, 300 ms, to begin with; **Cut** changes at once). **+** makes another: **Fade through colour** (the colour, and how far through it shows on its own), **Swipe** (an edge sweeps across), **Cover** (the next studio moves in over the last), **Uncover** (the last moves away), **Slide** (both move), each from any side, or **Wipe**, which reveals the next studio in one of 29 patterns (linear, diagonal, barn doors, iris, box, diamond, clock, fan, blinds, stripes, checkerboard, squares, circles, spiral, zig-zag, sine wave, curtain, burst, cloud and fractal) with a soft edge and the option to run backwards. **⋮** opens a transition's properties (changes show at once), renames or removes it, or adds it as a quick transition. A studio's right-click **Transition…** gives it a transition and duration of its own for going live with it. Changing studio again part way through starts from the picture showing. Sound follows the picture: sources only the old studio shows fade out, sources only the new one shows fade in. A **Stinger** plays a video over the change (one with transparency lets the studios show through): choose the video in its properties, and when into it the studios change; it lasts as long as the video. A video made with a **track matte** (a black-and-white copy beside or below the picture, the whole video as the matte, or **Another video** played with it) changes studios where the matte is white rather than at one moment. Its sound goes out with it, and can be heard in monitoring too; the studios' sound either crossfades or goes out until the change and comes back after it. Transitions are saved with the collection and follow undo; which one is chosen, and its duration, are not undone.

### Showing and hiding a source

a source can appear and go through a transition of its own, set under **Show and hide** in its inspector: any of the collection's transitions (a stinger fades), over its own time, or **At once**. It plays inside the source's box, wherever it is shown, studios inside studios and groups included; turned back part way, it goes back from where it got to.

### Studio mode

turn it on from the toolbar, **View → Studio mode** or the Transitions dock. The preview (left) shows the studio you click and edit; the program (right) is what is recorded and streamed, marked by a red dot in the studio list. **Take** puts the previewed studio on the program through the chosen transition; the quick transition buttons beneath take with their own transition. Drag the **T-bar** to mix by hand (with **Cut** chosen it mixes as a fade, as a cut has nothing in between): let go near the bottom and it takes, near the top and it gives up, anywhere else and it waits there, half way between the two, until you move it again or press **Take** (which finishes the mix, or goes to another studio you click). **Swap** (on by default) previews what was on the program after a take. **Copy** takes a copy of the layout as it is, so you can go on editing the same studio without it showing until the next take. With **Copy sources** as well, the copy keeps its own colours, images, text and slideshows as they were, so changing a colour, a picture or some words stays off the program too (screen and camera captures, media and sound are shared, as they cannot be opened twice; studios shown inside follow your edits). Sources only in the preview are shown there but not heard. Leaving studio mode makes the studio on the program the one you edit. Studio mode is remembered.

### Projectors and multiview

**View → Open a projector** shows the program, the preview or the **Multiview** in a window of its own; a studio's or a source's right-click menu opens one for it. Right-click a projector to put it **Fullscreen on** a screen (a screen holds one; the earlier one closes), back to **Windowed**, **Always on top** (it floats above other windows on every workspace), or to hide the cursor; Escape leaves fullscreen, then closes it. Projectors open again as you left them. The multiview shows the preview and program large with eight studios beside them (above, below, left or right), or a grid of 4, 9, 16 or 25 studios; its menu also turns studio names and safe-area guides on or off. The studio on the program is outlined red, the one in the preview in the accent colour. Click a studio to preview it in studio mode (or make it live otherwise); with **A click takes**, studio mode takes it too.

### Screenshots

**View → Screenshot of the program** (or of the preview), a studio's **Screenshot of the studio** and a source's **Screenshot of the source** save a full-size PNG in the recording folder.

### Preview

drag to move, drag handles to resize, drag the knob to rotate, Alt-drag a handle to crop; moves snap to the canvas edges and centre and to other items. **−** and **+** at the bottom right of the preview zoom (the size between them fits it again), as do a touchpad pinch and `Ctrl`+wheel; middle-drag or the wheel pans once zoomed; **View** has Fit (`Ctrl+0`), Actual pixels (`Ctrl+1`, one canvas pixel per screen pixel), Output pixels (one recorded pixel per screen pixel; the same as Actual pixels while recordings are canvas-sized) and zoom in/out. **View → Lock preview** stops anything moving by mouse or arrow keys while clicking still selects, which is useful during a live show. **View → Show overflow** draws a dashed outline around items that reach past the canvas edge. Both are remembered. The **context bar** under the preview names the selected source and its state, with quick buttons: play/pause and restart for media files, previous/play/next for slideshows, **Choose display…** or **Choose window…** for captures, a colour's colour, a text's words (Enter applies them), a capture device to switch to, plus edit transform, show/hide and lock. **View → Show context bar** hides it.

### Cameras and capture cards

add one from **Sources → +**. It opens at its best mode (most pixels per second); choose another mode, or adjust its picture controls, in the inspector. Controls are saved with the source and reapplied when the device is plugged back in. Many webcams label their uncompressed picture as limited range but send full range, which would clip highlights to flat white. With **Range: auto**, OmaBroadcast notices highlights or shadows piling up at the extreme ends of the range and switches that camera to full range. Choose **Limited** or **Full** to set it yourself. Capture cards that offer 10-bit modes (P010 or planar 10-bit) list them too, and their pictures keep all ten bits.

### Transforms

the inspector shows position, size, rotation, sizing, crop and mirroring; **Edit transform…** (inspector or right-click menu) opens the same controls in a larger window. X and Y place the **Position anchor** (top-left by default) before rotation; **Rotate around** picks the pivot separately (centre by default). Choose the same point for both to rotate around the position you typed. Changing either anchor leaves the item where it is. Sizing modes: **Free size**, **Stretch to box**, **Fit in box**, **Fill box (crop)**, **Cover box**, **Match box width**, **Match box height** and **Shrink to fit** (never enlarges). **Content in box** aligns the picture inside its box, and **Clip content to box** trims what overhangs. The right-click menu also rotates by 90° or 180°, fits, stretches or centres on the canvas, and resets the transform. Items inside a group are edited in canvas coordinates; locking a group locks the items inside it. Changing the canvas size keeps groups and nested studios in proportion. Everything follows undo, copied placement and collection save/load.

### Transparent media

videos and animations retain their alpha channel over the sources beneath them. Formats that keep their alpha include PNG video, QuickTime Animation, FFV1, ProRes 4444, transparent VP8/VP9 WebM and GIF. Images and media have an **Apply alpha in linear light** checkbox, enabled by default to preserve existing layouts. Turn it off for artwork that expects alpha to be applied to encoded colours before conversion to linear light. This source setting affects every reference, supports undo, and updates paused pictures without restarting playback or animation. The item’s blend-space setting separately controls how the result mixes with the backdrop. Full-resolution 4:4:4 chroma is retained, and files above 8 bits (10-bit HEVC, ProRes, FFV1 and the like) stay at their own precision. Files labelled HDR (PQ or HLG) or with BT.2020 colours are read as such (see Colour and HDR). An animated image over 256 MB is refused, and its line in the list says so.

Choosing **Open with → OmaBroadcast** on a picture or video in your file manager, or naming the file after `omabroadcast` in a terminal, puts it in the current studio as a source. An exported profile or collection is imported instead.

### Slideshows

adding a slideshow opens its image-list editor. Add several images at once or add folders, then use Up/Down, Replace and Remove to arrange the entries. Folders contribute readable images in name order without subfolders; repeated entries play again. Edit images reopens the list. Reload picks up folder changes, returns to the first image and preserves pause state. Use the source inspector for Previous/Next, Pause/Play, Restart and Stop. Manual mode waits for your next step; Stop returns to the first slide and pauses. Cut, fade, swipe and slide run through the CPU/Vulkan compositor, preserving transparency. Transition time fits within the slide interval. Disable Loop to stop on the last slide, or enable Hide after the last slide to transition to transparency. Hidden sources can continue, pause or restart when shown; shared visible references keep playback active. Shuffle avoids repeating the last image at a loop boundary. Settings support undo and collection save/load; playback position is temporary. Missing images and folders appear in Find missing files. Relinking repairs repeated/shared paths together with one undo step; automatic searches leave ambiguous filename matches for you to locate.

### Presentations

Where OmaShow is installed, **+ → Presentation…** (or **Studio → Add presentation…**) shows an OmaShow deck, or a PowerPoint or Keynote file OmaShow can read. OmaShow draws a picture for each moment its own show stops at: before each click's build and with the slide complete. The deck becomes a slideshow stepped by hand: **Next** and **Previous** in the source's settings, the context bar, your hotkeys, `omabroadcast ctl` and stream controllers step through it, with a short fade between pictures, and it stays on the last one. **Load again** in the source's settings reads the deck again after you change it in OmaShow. Movement within a slide, such as a build flying in, and films on a slide show as still pictures. An older OmaShow gives one picture a slide.

### Play last recording

**Tools → Play last recording** opens the last recording in a floating window of its own: the one you made last, or the newest in the recordings folder, and it moves to each new recording as it is saved (unless something is playing). It reads the file with the same FFmpeg that recorded it. **Space** plays and stops; **L** plays forward, and pressing it again goes 2 and 4 times as fast; **J** goes backward the same way, as still pictures without sound, since files cannot be played backward; **K** stops. **Left** and **Right** move one frame (with **Shift**, one second), **Home** and **End** go to the start and the end, and the bar along the bottom drags through it, with the timecode at the file's own frame rate. A meter for each channel shows the sound as the mixer's meters do, with the scale in dB; **Peak** beneath is the loudest moment so far (red if it reached 0 dB; click to start again), as true peak when the mixer's meters are set to it. The info button (**I**) lists the file's format, length, size and bit rate, its picture (codec, size, frame rate, bit depth, colour) and each sound track; with several tracks it says which one plays. The sound goes to the monitoring output when one is chosen, or the desktop's. While desktop sound, or the output it would play on, is being recorded, streamed or kept in the replay buffer, it stays silent and says so. On Hyprland the window floats and is kept out of screen captures, where it shows as a black box. HDR recordings are brought down to the screen's range, so they look as they should on an ordinary display.

### Media playback

select a media file to use Play/Pause, Restart, Stop and the seek bar in its inspector. Pausing holds the current picture; seeking while paused shows the new position without playing audio. Stop returns to the beginning and stays paused; Restart plays from the beginning. Playback speed ranges from 0.25× to 4× with pitch preserved. Speed is saved with the source and supports undo; position and pause state are temporary. Audio and video share the playback timeline, and transport changes clear the source's queued audio. Live phone/network inputs keep their live timing and have no file transport controls. A phone source takes H.264, HEVC, AV1, VP8, VP9 or MJPEG video with AAC, Opus, MP3, MP2 or AC-3 sound, in MPEG-TS, FLV or Matroska; sound in anything else is left out, and its line in the list says so. A new phone source makes its own random passphrase, shown in its inspector with **Copy** and **New passphrase**, and with what to type into the phone both ways: for an app with a passphrase field and for one that takes it in the address. It can be edited (10 to 79 letters, digits or `- _ . ~`), and changing it makes the source listen again. On SRT a sender with another passphrase or none is refused, and what it sends is encrypted. On RTMP, which has no passphrase, it is the address's first part (`rtmp://computer:port/passphrase/omabroadcast`, or server `rtmp://computer:port/passphrase` and stream key `omabroadcast`) and any sender naming something else is turned away, but nothing is encrypted, so someone watching the network can read it. Clear the passphrase for an app that cannot do either: then anyone who can reach the port can send a picture and sound, on air if the source is showing, so keep that to networks you trust. It is saved with the collection, in a file only you can read, and is not given to remote control clients. An exported collection leaves it out: a phone source opened from one makes a new passphrase, even one that had none. Files whose times jump, such as MPEG-TS files joined together or a camera's split clips, play straight on across the jump. The seek bar is available when the file reports a seekable duration. For faster playback or double-rate deinterlacing, raise the canvas frame rate to retain every picture or field moment.

### Profiles

open **File → Profiles…** to create, switch, duplicate, rename, remove, import or export video, recording and audio setups. New profiles start with defaults, with no desktop sound or microphone until you add them with **+** in Sources; Duplicate copies the current settings. The selected profile is remembered on the next launch. Switching keeps the current studio collection and restarts capture/audio to apply the profile, using saved local capture grants. Finish any recording before changing profiles. Removed profiles go to the bin. Exports contain settings, device choices and file paths, but omit capture permission tokens and collection links; imports create a new profile and keep your current collection. A native `profile.json` can also be imported. Choose devices available on the receiving computer when transferring a setup.

### Direct capture

the Sources menu offers **Direct display…**, **Direct window…** and **Follow focused window**. They need a compositor that supports the capture protocols; elsewhere the sheet says so and offers the desktop picker. Choose a target without opening the desktop portal picker. A selected window stays selected when its title changes; after a reconnect or restart, its saved application and title must match uniquely. Following focus shows black when no window is focused. **Direct capture…** in the inspector changes the choice; **Desktop picker…** switches back to the portal. Choices, cursor visibility and region bounds support undo and collection save/load. Direct capture negotiates DMA-BUF layouts with the compositor and selected GPU, using a bounded buffer pool. CPU rendering, unavailable layouts and rejected allocations/imports fall back to shared memory. Both paths preserve alpha and inverted rows, and keep rotated or mirrored displays upright at their physical pixel dimensions. Region bounds use these upright pixels, including on fractionally scaled displays.

### Display regions

choose **Sources → + → Display region…** and pick a display. In its inspector, choose **Draw region…** and drag a rectangle on the display itself: on Hyprland OmaBroadcast steps aside while you draw (Esc cancels), elsewhere you draw on a snapshot of the display and choose **Use region**. You can also enter X, Y, width and height in captured display pixels; a width or height of 0 extends to that edge. **Use full display** clears the region. Changes apply to all instances of the source, support undo and are saved with the collection. The display capture stays open while you edit. Each instance still has its own placement, crop and scaling. Coordinates clamp to the current display size if it changes.

### Interlaced video

the source inspector offers Discard field, Linear, Blend and Motion adaptive modes, each at normal or double field rate. Discard repeats the selected field's rows; Linear interpolates missing rows; Blend smooths adjacent field moments; Motion adaptive retains static detail and interpolates moving areas. Choose Automatic, Top first or Bottom first field order. Automatic uses frame metadata and defaults to Top first when unavailable. For both field moments, choose a 2× mode and set the canvas to at least 50 fps for 25 fps input, or 60 fps for 30 fps input. Audio retains its normal speed. Settings support undo and collection save/load. Processing runs on Vulkan with a matching CPU fallback, before source noise reduction. Interlaced FFV1 uses software decoding where the Vulkan decoder loses field metadata.

### Video filters

right-click a source and choose **Filters…**, or use **Edit filters…** in its inspector, to add, switch off, reorder, edit or remove up to 32 filters. Every number is a slider with a button to put it back, and outside Colour wheels it shows what it is set to; click one and use the arrow keys to move it a step at a time. The eye beside a filter turns it off or on and keeps its settings. Colour correction can no longer be added, as Colour wheels does its work; one already on a source still runs and can still be edited. They run top to bottom on the source's picture, after deinterlacing and noise reduction, wherever the source is shown. Available: **colour wheels** (lift, gamma, gain and offset, each a wheel whose point pushes the shadows, mid-tones, highlights or everything towards a colour, laid out as the vectorscope shows colour, and a level; then contrast about a pivot, and saturation; drag a point, Shift for fine, double-click to centre it; a drag is one undo step), sharpen, chroma key (green, blue, magenta or any colour, with similarity, edge softness and spill reduction), colour key, luma key, apply LUT (.cube 1D/3D files, or Hald, tiled or strip LUT pictures, trilinear or tetrahedral, with an amount), image mask/blend (a picture's alpha or brightness as a mask, or multiply, add or subtract its colour), crop/pad (from each edge or as a box; negative amounts add transparent padding), scaling/aspect ratio (a size or a preset, five sampling filters, stretch, fit or fill), scroll (speed across and down, a shown size, looping or crossing), blur, drop shadow (inside the picture: pad it with Crop/pad first to give the shadow room), render delay and, for files, cameras and captures, video delay. **Remove background (AI)** finds the people in the picture and takes everything else away, with no green screen: it knows people only (not objects or pets) and works best on one or two people from the waist up. **Background** is **Take away** (see-through, for putting something behind) or **Blur** (the room kept, out of focus, as on a video call, by **Blur**, a share of the height). The outline is steadied over time where the picture holds still, so its edges do not shimmer, and at Fast it is brought to the picture's own edges for crisper hair. **Quality** sets how closely it looks (Fast, Balanced or Best), **Spread over** shares the work out over 1, 2 (the default) or 3 frames, so each costs a half or a third as much while the outline follows movement a frame or two later (the first outline is always made whole), and **Tighten edges** narrows the soft edge round people when a rim of the background shows. It runs on the graphics card only; without one, if the card stops answering during a show, or if the filter cannot run for any reason such as no memory left, the source is hidden rather than shown with its background, and the status line and the sheet say so. It uses MODNet (Apache-2.0). **Light wrap**, put after Chroma key or Remove background (AI), lets the light of whatever is behind the source in the studio spill a little way over its edges, so a keyed person looks lit by the scene rather than pasted on: **Style** is **Add light** (the light behind brightens the edges) or **Blend colour** (the edges take on the colours behind, darker or lighter, which suits dark scenes), **Width** is how far in it reaches as a share of the studio's height (so it looks the same at 1080p and 4K), and **Strength** how much of the scene reaches the edges. It takes the light from what is actually behind, so the same source picks up a different glow in each studio, and while it is selected the filters preview shows the studio being edited (**In the studio**), so its effect is seen as the sliders move; **In the studio** works for any filter. For HDR there are two more: **HDR tone map** brings an HDR source's highlights down into SDR, from its brightest (**Source peak**, in nits) to SDR white, along a gentle roll-off (BT.2390), Reinhard, or a plain clip; **SDR on HDR** shows an SDR source's white at a brightness of its own in an HDR picture (or multiplies its light). The keys, LUTs, blend modes and sRGB blend space work on SDR values, so they clip an HDR source's highlights; put a tone map first if that matters. Keys never cut harder than a 2 % edge. A filter whose file is missing is left out and named in the sheet. **Copy**/**Paste** (in the sheet, the inspector or the context menu) add one source's filters to another's. **Scopes** (tick **Scopes** under the preview; on by themselves for the colour filters) show the preview beside it as a **waveform** (BT.709 brightness across the picture, 0 to 100), an **RGB parade**, a **vectorscope** (Cb/Cr, with the 75 % colour-bar targets and the skin-tone line) or a **histogram**; see-through parts are left out. Filters follow undo and collection save/load; Crop, Scaling and Scroll change the source's size as placement sees it. Delays hold at most 1 GB of pictures, so long delays at large sizes are shortened.

Use **Sources → + → Microphone or audio input**, **Desktop sound**, **Audio output** or **Application audio** to bring in a sound. An input already in use is greyed out. An application source includes its playback streams as they appear and reconnects when the application restarts. Choose a different target in the mixer or source inspector. Source audio, including a microphone added with **+**, follows visibility in the live studio, including nested studios. Desktop sound, the Microphone channel that **Set up for…** adds, and **Sound for every studio…** carry on in every studio. If you want only one application's sound, leave Desktop sound out, or remove it with **X**. If PipeWire stops or restarts, the status line says so, a recording or stream carries on without sound or capture devices, and everything reconnects when PipeWire is back: sources, devices, monitoring, the virtual camera, screen captures with a saved choice (one without says it failed; choose it again in its inspector), and browser sources, whose pages reload.

### Global audio devices

choose **Sources → + → Sound for every studio…** to add any number of audio inputs or output captures. Name each channel and choose its device. They remain active across studios and collections, reconnect to saved devices, and have the same filters, monitoring, track routing, hold controls and hide/show options as other mixer channels. Settings are saved in the profile. Choose **Off** to disconnect a capture, or **Remove** to delete its channel. Capturing a device twice mixes it twice, so mute unused Desktop or Microphone channels when adding replacements.

### Audio controls

type a gain in dB (0 dB is unchanged; `-inf` is silence). Open **Advanced** on any channel for mono downmix, stereo balance and a sync offset from −1000 to +2000 ms. Positive offsets delay audio; negative offsets advance it by buffering output. Stopping waits for buffered audio through the last video frame while monitoring continues. Missing input is silence. Source controls follow undo and collection save/load; global device, desktop and microphone controls are saved in the profile.

### Push-to-talk and push-to-mute

open a channel's **Advanced → Hold controls** to enable either action, enter a single local shortcut (for example `F9` or `Ctrl+Shift+T`), and set its release delay from 0–5000 ms. Talk keeps audio open after release; mute keeps it silent. Hold buttons also appear on the mixer. Normal Mute always takes priority, and push-to-mute wins when both actions are held. These controls affect monitoring and every assigned recording track. Local shortcuts work while the main window is active, outside dialogs and text fields; losing focus cancels local holds immediately.

Choose **Apply global shortcuts** to bind all enabled hold controls through the desktop's shortcut dialog. The returned bindings are shown in Advanced and work while other apps have focus. Apply again after changing enabled actions or keys; successful setup is restored on the next launch. **Turn off global shortcuts** also cancels pending setup. Closing or losing the portal clears its held state. The desktop must support the GlobalShortcuts portal; local shortcuts and mixer buttons remain available when it does not. Shortcut preferences follow profiles/collections; held state is never saved.

### Mixer visibility

choose **Hide** beside a channel name to hide its strip. Open **Channels** above the mixer to restore individual channels or **Show all channels**. Hidden channels keep playing, recording and responding to shortcuts. The channel list includes inactive sources; **Active sources only** still controls when their strips appear. Source visibility preferences follow undo and collection save/load; global device, desktop and microphone visibility follows the profile.

### Meters

open **Meters** above the mixer or **Settings → Meters** for sample peak or true peak, fast/medium/slow decay (24/12/6 dB per second), horizontal or vertical strips, and colour overrides. Each mixer strip has labelled bars for its speakers, measured after its filters and fader. The numeric reading holds the maximum; click it to reset the maximum and clipping indicator. True peak estimates peaks between samples without changing the output audio and uses more processing. Meter preferences are saved in the profile; **Use theme colours** restores live theme colours.

### Monitoring

choose an output below the mixer, under **Monitoring output**, then select **Monitor only** or **Monitor and output** in a channel's Advanced controls. **Solo** changes only what you monitor. Monitoring pauses if that output is also captured by an audible desktop/output channel; mute that capture or choose another output. A missing device stays selected and reconnects when it returns. **Active sources only** hides channels outside the live studio.

### Audio filters

press the waveform button on any mixer channel (**FX** with vertical meters) to add, bypass, reorder or remove up to 16 filters. Their numbers are sliders too. Available now: gain, noise gate, RNNoise speech suppression, spectral noise suppression, compressor, limiter, expander, upward compressor, polarity inversion, 3-band EQ, de-esser and delay with dry/wet and feedback. Filters run top to bottom after summing a channel's inputs, before mono downmix, balance and the fader. Monitoring and all assigned recording tracks receive the same processed sound. Source filters follow undo and collection save/load; global device, desktop and microphone filters are saved in the profile. EQ uses shelves at 120 Hz and 6 kHz plus a 1 kHz mid band. The limiter controls sample peaks at its position in the chain; later gain or summed channels can exceed that ceiling. RNNoise is intended for speech; spectral suppression reduces quiet frequency bands with adjustable threshold and reduction. Suppression adds processing delay (spectral: 21.3 ms at 48 kHz; RNNoise measured 30 ms at 48 kHz and 41.45 ms at 44.1 kHz with the current system library). Use the channel sync offset when compensating for this delay.

### Audio format

choose **44.1 kHz** or **48 kHz**, and **Mono, Stereo, 2.1, 4.0, 4.1, 5.1 or 7.1**, in **Settings → Audio**. The format applies to capture, media decoding, filters, monitoring and all recorded tracks. Speaker labels on the meters show the channel order. Surround recordings need compatible players; stereo monitoring devices downmix the sound. Format changes are available while nothing is recording, streaming, buffering a replay or on the virtual camera, and restart audio and media playback. Screen and camera capture remain open. RNNoise resamples internally when using 44.1 kHz.

### Low latency

enable **Settings → Audio → Low latency** for responsive monitoring. Audio runs independently of video rendering. Buffering includes the measured age of captured audio, so a slower application or device can add latency. If a device crackles, switch back to standard buffering; latency mode can be changed while nothing is recording, streaming, buffering a replay or on the virtual camera. Sync offsets still add their requested buffering.

### Finishing recordings

Stop finishes the audio and encoder queues in the background. The button shows **Finishing…** until the file is closed; monitoring and the interface remain active. **Stop and quit** waits for this completion before closing the app.

### Audio tracks

assign each channel to any of tracks 1–6 in Advanced, then choose which tracks to save in **Settings → Recording → Audio tracks**. Each selected track is encoded separately in MKV, MP4 or MOV. Monitor-only channels stay out of every recorded track. Selecting no recording tracks creates a video-only file.

### Formats

Matroska (MKV), MP4, MOV, fragmented MP4/MOV, hybrid MP4/MOV, MPEG-TS, FLV and HLS (a playlist with segments beside it). MKV, fragmented, hybrid, MPEG-TS, FLV and HLS files still play if the recording is cut off by a crash or power cut; plain MP4 and MOV need a clean stop. Hybrid MP4/MOV write a crash-proof file and turn it into an ordinary one when you stop. Chapters are kept in MKV, MP4, MOV and the hybrid formats; MP4 and MOV chapters always begin at the start of the file, so a first marker later on gets a "Start" chapter before it. **Custom** records into any other container FFmpeg can write, by its own name (`ffmpeg -muxers` lists them, for example `nut`, `avi` or `mxf`); the file takes that container's usual extension, and the settings say whether it keeps chapters and warn when FFmpeg has no such container or it holds no picture. AV1 is left out of MPEG-TS and HLS, because FFmpeg writes it there but cannot read it back; the same goes for SRT and HLS streams. Pictures keep the moment they were drawn, so a stretch the canvas skipped is a gap in the file, never repeated frames, with the sound still in step.

- `Ctrl+Shift+D` add a display

### Your own keys

**Settings → Hotkeys** lists every action: recording, streaming, the replay buffer, the virtual camera, screenshots, studio mode, Take and the quick transitions, showing each studio, choosing a transition, showing or hiding each source, media and slideshow controls, muting a channel, and switching a filter on or off. Click an action's key, then press the key you want (with Ctrl, Alt, Shift or Super); Backspace clears it, and a key used twice is pointed out. **Keys work** chooses whether they run always, only while OmaBroadcast has focus, or only while another app has it. Keys for studios, sources, transitions and filters belong to the collection; the others to the profile. They work while the window is active, outside dialogs and text fields; **Apply global shortcuts** asks the desktop (through its GlobalShortcuts portal) to make them, and the push-to-talk keys, work while other apps have focus.

### Automatic studio switcher

**Tools → Automatic studio switcher…** changes the program's studio when another window gets the keyboard (Hyprland). Add a rule, choose whether it looks at the window's class (its app) or its title, type a pattern (a regular expression, matched anywhere and without regard to case, e.g. `firefox|chromium`) and pick the studio. Rules are tried top to bottom; **When nothing matches** either stays where it is or goes to a studio. Your own OmaBroadcast windows never switch anything, and in studio mode the studio you are editing stays. The rules are saved with the collection.

### Scripts

**Tools → Scripts…** runs JavaScript files you add; each can be switched off, loaded again after you change it, or removed (the file stays). A script sees one object, `omabroadcast`:

- `omabroadcast.run(action, argument)` runs any action from **Settings → Hotkeys** / `omabroadcast ctl list` (the same names), and returns `""` when done or why not;
- `omabroadcast.state()` says what is running: `recording`, `streaming`, `replay`, `virtualCamera`, `studioMode`, `studio`/`studioName` (being edited), `program`/`programName`, `transition`, `profile`, `collection`;
- `omabroadcast.actions()` lists the actions there are now;
- `omabroadcast.on(event, function (data) { … })` follows `studio` and `program` (`{id, name}`), `recording` and `streaming` (`{recording}` / `{streaming}`), `replaySaved` and `screenshot` (`{path}`) and `focus` (`{class, title}`, with the automatic studio switcher on);
- `omabroadcast.settings({ delay: { label: "Delay", type: "number", default: 5 } })` gives the script a form (types `text`, `number`, `bool`, `studio`), shown with the gear beside it under **Tools → Scripts**; it returns the values, `omabroadcast.setting("delay")` reads one later, and a change arrives as the `settings` event;
- `setTimeout`, `setInterval`, `clearTimeout` and `clearInterval` keep time; `print`, `console.log` and `omabroadcast.log` write to the log under the list.

```js
// Back to the main studio five minutes after going live.
omabroadcast.on("streaming", function (d) {
  if (d.streaming) setTimeout(function () { omabroadcast.run("studio.show", "Main"); }, 5 * 60 * 1000);
});
```

Each script runs on its own, so a slow one never holds up the window, and one that runs on without a break for five seconds is stopped. Scripts cannot read files or reach the network.

### Output timer

**Tools → Output timer…** stops each recording, or ends each stream, after the minutes you set. A paused recording's pause does not count, and the time left shows beside the clock.

### From a terminal or your compositor

`omabroadcast ctl ACTION [ARGUMENT]` runs any action in the running app, for example `omabroadcast ctl record.toggle`, `omabroadcast ctl studio.show "Close up"`, `omabroadcast ctl item.toggle Logo` or `omabroadcast ctl audio.mute "USB Microphone"` (a sound by its name in the mixer; `desktop` and `microphone` mean the Desktop and Microphone strips, if you have them). Studios, sources and transitions can be named by name or id. `omabroadcast ctl list` shows every action with what it can take now, and `omabroadcast ctl status` what is running. It exits with 0 when done, 1 when the app refused (and says why), 2 when the app is not running, and 3 when it refused only because it is still checking which encoders work just after starting, so a script can wait and try again; `omabroadcast ctl status` shows `checkingEncoders` until then. `omabroadcast FILE`, or **Open with** in a file manager, adds a picture or video to the current studio, or imports an exported profile or collection; with a copy running, that copy takes it. To bind keys in Hyprland:

```
# hyprland.conf
bind = SUPER, F9, exec, omabroadcast ctl record.toggle
bind = SUPER, F10, exec, omabroadcast ctl take
```

or, where the bindings are Lua (Omarchy 4, `~/.config/hypr/bindings.lua`):

```lua
o.bind("SUPER + F9", "Record", "omabroadcast ctl record.toggle")
o.bind("SUPER + F10", "Take", "omabroadcast ctl take")
```

Scripts can talk to the same place directly: the app listens on `$XDG_RUNTIME_DIR/omabroadcast.sock` (only you can connect) for one JSON object per line, `{"id": 1, "action": "studio.show", "argument": "Close up"}`, and answers with `{"id": 1, "ok": true, "result": {…}}` or `{"ok": false, "error": "…"}`, with `"retry": true` when asking again shortly will do; `list` and `status` work there too.

### Remote control (Stream Deck, controllers, phone apps)

**Tools → Remote control…** lets stream controllers and apps that speak the version 5 WebSocket remote-control protocol connect: Stream Deck plugins, Bitfocus Companion, Touch Portal, StreamController on Linux, and the many web and phone remotes. Switch on **Allow remote control**, then point the controller at the address the sheet shows (`ws://` this machine's address and port `4455` unless you change it) with the password shown there; **Copy** puts it on the clipboard and **New** makes another (anything connected signs in again). With **Other devices on the network can connect** off, only apps on this computer can. In the controller's terms, studios are *scenes*, sources and the desktop and microphone channels are *inputs*, and items in a studio are *scene items*. Switching studios (and studio mode's preview, Take and T-bar), recording, pausing, splitting and chapters, streaming, the replay buffer, the virtual camera, muting and volume, showing and hiding sources, filters on and off, transitions and their duration, media and slideshow controls, screenshots of studios and sources, projectors, collections, profiles, and every action from **Settings → Hotkeys** (by its `ctl` name, e.g. `studio.show|c3`) all work, and the controller hears about each change as it happens. Remote control is off until you switch it on, and never on in safe mode. The password is kept in plain text in the app's settings (`~/.config/omabroadcast/global.json`, readable only by you), since controllers need it typed in anyway; use one you use nowhere else.

## Settings

Settings has a page for each part, picked from the list on its left: Video, Audio, Meters, Recording, Replay buffer, Streaming, Virtual camera, Hotkeys and General. It reopens on the page you last used.

- **Canvas**: a size from the list or your own; until you choose, it follows the first display you capture. A collection remembers the size its layout is at: opened under a profile or on a display with another canvas, the layout is scaled to fit, and it comes back when you go back.
- **Frame rate**: 24 to 120, 23.976, 29.97 and 59.94, or any fraction (frames in so many seconds). It takes effect at once (the picture restarts, and checks the encoders again), or once recording, streaming, the replay buffer and the virtual camera stop. Choosing a capture device's mode at another rate (a capture card at 50, say) sets this to it, so it is set in one place; a device left on **Best available** runs its largest picture at this rate when it offers one. The page says when a device in the collection sends another rate.
- **Scaling**: how the canvas is scaled when a recording or stream is a different size from it. **Area** (the default) averages everything each pixel covers: smooth, with no shimmer on fine detail. **Bicubic** and **Lanczos** keep text and edges sharper, Lanczos the most. **Bilinear** is the cheapest and softest, and fine patterns can shimmer when it shrinks a lot. All of them work in linear light.
- **Colour format, colour space, range, SDR white and HDR peak**: see Colour and HDR above.
- **Encoder**: "Best available" ranks working encoders for recording by codec, hardware capability and the compositing device. The list only shows encoders that actually opened on this machine (`omabroadcast --probe` prints the full table). Whenever the canvas changes, each hardware encoder that opens at its size is also timed for a moment, and one that cannot keep up with the frame rate there (a chip whose AV1 block manages 33 frames a second at 4K while its HEVC block does 137) is listed as "only 33 of 60 frames a second" and not picked as Best available, unless every encoder on the graphics card is that slow: then the fastest of them is used, since one on the processor would be slower still. Each is named by its codec and where it runs: H.264, HEVC (H.265) and AV1 on the processor or a graphics card, and **APV** on any graphics card through Vulkan. APV is for recordings you will edit: every frame stands alone, in 10-bit 4:2:2, so it cuts and grades easily. Instead of rate control it has a **Quality** choice: **Light**, **Standard** or **High**, each at least as good as ProRes LT, 422 and HQ respectively, at about their size on average. The quality is held steady and the size follows the picture, so camera pictures come out larger than ProRes and screen recordings smaller. A Vulkan encoder (APV, or H.264 and HEVC through Vulkan) on the graphics card that draws the picture takes each picture without it leaving the card, which is what lets a laptop graphics card record APV at 4K and 50 or 60 frames a second; on another card, pictures are copied across as for any encoder. APV is never picked as "Best available", isn't offered for streams, and belongs in a QuickTime (MOV) file, which is what editors expect. Anything built on FFmpeg 9 plays it.
- **Quality**: a CRF-style scale, 23 by default; 18 is near lossless, 30 is small.
- **Rate control**: constant quality (the quality scale), constant or variable bitrate (kb/s, with a peak for variable), a fixed quantiser, or lossless where the encoder has a lossless mode.
- **Format** (see Formats above) and **Folder**, a full path or one starting with `~/`.
- **Audio codec**: AAC (plays everywhere), Opus (best at low bitrates), FLAC and ALAC (lossless) or uncompressed PCM (16-bit, 24-bit, 32-bit float), where the format can hold it.
- **New file every** so many minutes or megabytes (0 never splits). Each file starts on a keyframe; nothing is lost or repeated between them.
- **Advanced**: keyframe interval, B-frames, look-ahead, and the encoder's own preset, profile and tune names and `key=value` options, passed as typed. An option the encoder doesn't know stops the recording from starting and names it. **Split encode** appears when the encoder can share each picture between several engines (some graphics cards have two or three), for sizes and frame rates one can't keep up with. **Container options** are the container's own `key=value` options, for any format; one it doesn't know stops the recording from starting and names it.
- **File name**: a pattern with date codes (`%Y` year, `%y` short year, `%m` month, `%d` day, `%H` hour, `%M` minute, `%S` second) and names (`{studio}`, `{profile}`, `{collection}`, `{width}`, `{height}`, `{fps}`), shown as a live preview. **No spaces** uses `_` instead. Characters other systems refuse (`/ \ : * ? " < > |`) become `-`. An existing file is never overwritten: the new one is numbered, as in `Interview (2).mkv`.
- **Bar and tray**: on Omarchy, OmaBroadcast puts an icon in the bar the first time it opens. Clicking it shows or hides the window, or opens the app when it is closed; right-clicking it starts or stops recording, goes live or ends the stream, works the replay buffer and virtual camera, and quits. It turns red with a timer while recording or live (red only on a bar down the side of the screen). While it is there it takes the tray icon's place; **Show an icon in the Omarchy bar** turns it off. Elsewhere, an icon in a tray offers the same. Optionally keep running when the window is closed, or start with it hidden. Quit from the icon's menu, **File → Quit** or `Ctrl+Q`.
- **Confirm**: ask before starting and/or stopping a recording or a stream; this covers the buttons, the menus, `Ctrl+R` and the bar or tray icon. Quitting while recording or streaming always asks.
- **Hide OmaBroadcast from screen capture** (off by default, Hyprland): its windows show as black in display captures, in OmaBroadcast and in other apps (screenshots included), so the preview never repeats inside itself. It applies at once and comes back after Hyprland reloads its config; nothing is written to your Hyprland config.

## When something goes wrong

### Log

**Help → Log** shows what OmaBroadcast has reported this run. Choose how much to see (everything, information and up, warnings and errors, or errors only), type to search, **Copy** the lines shown to paste into a bug report, or **Save log…** to keep the whole run in a file. This run's log and the one before are also kept in `~/.local/state/omabroadcast/` (`omabroadcast.log` and `omabroadcast.previous.log`, each at most about a megabyte). Nothing is ever sent anywhere.

### After a crash

if OmaBroadcast did not quit properly last time (it crashed, was killed, or the computer lost power), it says so when it next starts, before it restores anything. **Show the log** reads what that run logged before it ended, including the signal it died of; **Save the log…** keeps it in a file for a bug report. Then choose **Start normally** or **Start in safe mode**.

### Safe mode

for finding what keeps going wrong. Choose it after a crash, or start with `omabroadcast --safe-mode` (not while a copy is running: that one comes forward instead, so quit it first). Screen and window captures are not restored (and no share picker opens), the virtual camera, streams and replay buffer start only when you start them, video filters leave out their LUT and picture files, and the picture is drawn on the CPU instead of the graphics card, so a source using Remove background (AI) is hidden. Everything you have is left as it was; a banner across the window says safe mode is on, and **Restart normally** quits and starts again as usual.

### Repair

**Help → Repair…** checks that every studio collection and profile still reads. Ones that don't (a damaged file, or one from a newer version) can be **set aside**: moved out of the way so OmaBroadcast starts clean. The profile or collection it is opening is set aside by itself if it does not read, never saved over, and the status line says where it went. **Reset layout…** puts the docks, folded panels, preview, studio list, multiview and projectors back as they were at first, keeping recording, streaming and other settings. **Clear stale grants…** forgets saved screen and window choices whose sources or collections are gone. Each asks first, and nothing is deleted: what is moved or changed goes into a dated folder under `~/.config/omabroadcast/set-aside/`, from where you can copy it back.

## Translating it

OmaBroadcast follows the desktop's language when it has a translation for it. To add a language:

1. Copy `translations/omabroadcast.ts` to `translations/omabroadcast_<language>.ts` (for example `omabroadcast_de.ts`), set `language="de_DE"` on its `<TS>` element and translate it with Qt Linguist (`linguist6`) or any text editor.
2. Add `translations/omabroadcast_de.ts` to the `TRANSLATIONS =` line in `omabroadcast.pro`.
3. Run `./bin/build`; the translation is built into the binary.

After the interface changes, refresh the template and every translation with `lupdate -no-obsolete omabroadcast.pro -ts translations/*.ts` (lupdate is in `qt6-tools`).
